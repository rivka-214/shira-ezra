# אפיון טכנולוגי — אתר שירה עזרא

מסמך להעברה למפתחת. תואם לאפיון התוכן שסופק על ידי הלקוחה ולשפת המותג.

**מקרא במסמך זה**

| סימון | משמעות |
|---|---|
| **דרישה** | נקבע על ידי הלקוחה / אפיון התוכן |
| **תוכן שסופק** | טקסט או מבנה שכבר קיים בחומרים |
| **המלצה** | הצעה מקצועית — לא לבצע כאילו הלקוחה ביקשה |
| **חסר / נדרש החלטה** | לא סופק או לא אושר; אין להמציא |

## 1. מטרת המערכת

**דרישה.** אתר תדמית ויזואלי עבור שירה עזרא, צלמת ועורכת וידאו.

האתר נועד ל:

- הצגת שלושת תחומי הפעילות: וידאו, תדמית ועסקים, אירועים
- הצגת עבודות, המלצות לפי תחום, וחבילות בתחום האירועים
- חוויית משתמש ויזואלית ומקצועית
- הובלה ליצירת קשר
- הצגת לוגואים של לקוחות
- התאמה למחשב, טאבלט ומובייל

**דרישה — מה האתר אינו:**

- לא CMS
- לא מערכת הזמנת תאריכים / יומן זמינות
- לא One Page — ארבעה עמודים נפרדים
- כפתור «שריון תאריך» מוביל לטופס יצירת קשר בלבד

## 3. Technology Stack

### 3.1 בחירה מומלצת

**המלצה.** האתר הוא תדמית עם SEO וביצועים; אין Backend מלא ואין CMS.

| מנגנון | טכנולוגיה | למה |
|---|---|---|
| Framework | Next.js (App Router) | SEO, ביצועים, Routing, Metadata API |
| שפה | TypeScript | טיפוסיות וסדר |
| UI | React | בסיס ל־Next.js |
| Styling | Tailwind CSS | התאמה מהירה לשפת המותג (לבן, דיו, כחול, ירוק, גרדיאנט) |
| אנימציות | CSS קודם; Framer Motion רק אם CSS לא מספיק | לוגואים נעים, מעברי עמוד עדינים |
| תמונות | `next/image` | אופטימיזציה, lazy, CLS |
| סרטונים | HTML5 `<video>` | Autoplay muted loop playsInline |
| אחסון מדיה כבדה | Cloudinary או CDN וידאו | סרטון Hero לא בתוך Git |
| תוכן | קבצי TypeScript ב־`src/data` | עדכון בלי CMS |
| טופס | Server Action או `POST /api/contact` | מפתחות לא בדפדפן |
| מייל | Resend | שליחה למייל של שירה |
| אנטי-ספאם | **המלצה:** honeypot + rate limit; Turnstile רק אם יש ספאם בפועל | הלקוחה לא ביקשה CAPTCHA |
| SEO | Next.js Metadata API | title/description/OG לכל עמוד |
| Analytics | **המלצה בלבד:** GA4 + Search Console | לא חובה |
| Git | GitHub | גרסאות |
| Hosting | Vercel | מתאים ל־Next.js, HTTPS, CI |
| דומיין | דומיין של הלקוחה → Vercel | **חסר:** כתובת הדומיין |
| SSL | Vercel | אוטומטי |

### 3.2 מה לא להכניס

אין סיבה לפרויקט זה ל: Express נפרד, MongoDB/PostgreSQL, Firebase/Supabase, מערכת משתמשים, CMS, מערכת הזמנות, Redis, Docker.

### 3.3 הערה על הריפו הנוכחי

בפרויקט `shira-ezra` קיימת כרגע תבנית **Vite + React + TypeScript + React Router**.  
**המלצה:** מעבר ל־Next.js לפי הטבלה למעלה.  
אם מחליטים להישאר ב־Vite: לשמור על אותם Routes, אותם רכיבים ואותו מנגנון טופס (למשל Serverless function או שירות Formspree), ולקבל פשרה ב־SEO ובאופטימיזציית תמונות.

**נדרש החלטה:** Next.js+Vercel (מומלץ) או המשך Vite.

## 5. Pages & Routing

| עמוד | URL | Anchor טופס |
|---|---|---|
| בית | `/` | `#contact` ב־footer |
| וידאו | `/video` | `/video#contact` |
| תדמית ועסקים | `/business` | `/business#contact` |
| אירועים | `/events` | `/events#contact` |

אין עמודים נוספים (אין אודות / FAQ) אלא אם הלקוחה תוסיף.

### 5.1 קפיצות מעמוד הבית (**דרישה**)

ליד כל תווית:

| תווית | דוגמאות | המלצות | איך זה עובד | בואו נתקדם |
|---|---|---|---|---|
| וידאו | `/video#works` | `/video#reviews` | `/video#why` (בעמוד וידאו זה «למה איתי», אין תהליך 5 שלבים) | `/video#contact` |
| תדמית ועסקים | `/business#works` | `/business#reviews` | `/business#how` | `/business#contact` |
| אירועים | `/events#works` | `/events#reviews` | `/events#how` | `/events#contact` |

IDs חובה בסקשנים: `works`, `reviews`, `how` / `why`, `contact`.

### 5.2 ניווט בין עמודים

**דרישה:** שלוש התוויות בעמוד הבית מובילות לעמודים נפרדים.

**המלצה (לא דרישה):** Header מינימלי עם לוגו + 3 קישורים + CTA לטופס, לתפריט המבורגר במובייל. הלקוחה ביקשה לא להוסיף תפריט אלא אם נדרש לשימושיות.

אין לשנות משמעות טקסטים. תיקוני כתיב קלים (למשל «תאום»→«תיאום» בכותרת תהליך) רק אם הלקוחה מאשרת; באפיון התוכן נשמר הנוסח שסופק.

### 7.2 מבנה data לפי תחום

**business.ts:** hero, valuePoints (3), whyNow (3, «אחד ליד השני זז ליד הגל»), envelope (4 ✔), projects, recommendations, process (5 שלבים), cta.

## 8. Contact Form

### 8.1 שדות

**דרישה:** שדות רלוונטיים ליצירת קשר; כפתור «שליחת טופס»; שליחה לשירה.

**המלצה (לא אושר במפורש):**

| שדה | סוג | חובה |
|---|---|---|
| שם | text | כן |
| טלפון | tel | כן |
| אימייל | email | **המלצה:** כן |
| הודעה | textarea | לא |
| תחום עניין | select: וידאו / תדמית ועסקים / אירועים | **המלצה** — אפשר למלא אוטומטית לפי העמוד הנוכחי |

**נדרש החלטה** על רשימת השדות הסופית.

### 8.2 התנהגות

1. Validation בצד לקוח + שרת  
2. מצב Loading; חסימת שליחה כפולה  
3. הצלחה: הודעת הצלחה (נוסח מדויק **חסר** — המלצה: «הטופס נשלח. ניצור קשר בהקדם.»)  
4. כשל: הודעת שגיאה ברורה  
5. CTA «שריון תאריך» / «דברו איתי» / «שיחת ייעוץ» → גלילה ל־`#contact` באותו עמוד, לא למערכת הזמנות

### 8.3 API

`POST /api/contact` או Server Action.

Payload:

```json
{
  "name": "...",
  "phone": "...",
  "email": "...",
  "message": "...",
  "interest": "video | business | events"
}
```

יעד: `CONTACT_EMAIL=Sh0548445344@gmail.com` (דרך env, לא בקוד).

### 8.4 אבטחה (**המלצה**)

Validation שרת, אורך מקסימלי, דחיית ריק, rate limiting, honeypot, אין API keys בצד לקוח.

## 10. Responsive, ביצועים, נגישות, SEO

### 10.1 Responsive (**דרישה**)

Desktop / wide / laptop / tablet / mobile.  
לא רק scale של דסקטופ: עמודות גלריה, כרטיסי חבילות, Hero, וידאו, גודל כפתורים.

עמוד תדמית: בלוק «למה עכשיו» — «אחד ליד השני זז ליד הגל».  
עמוד אירועים: 3 שלבים — «אחד מתחת לשני זז ליד הגל».

### 10.2 ביצועים

`next/image`, lazy לגלריות מתחת ל־fold, פיצול קוד לפי route, דחיסת וידאו, אנימציות CSS, Server Components כשאפשר. עמוד הבית טוען רק שאווירל + UI כניסה, לא את כל הגלריות.

### 10.3 נגישות

HTML סמנטי, alt, H1 אחד לעמוד, ניגודיות (ירוק על לבן לבדוק — אולי ירוק על דיו לכפתורים), focus, מקלדת, labels, `prefers-reduced-motion`.

### 10.4 SEO (**המלצה** לנוסחי מטא — הלקוחה לא סיפקה)

לכל עמוד: title, description, OG, canonical, favicon.

| עמוד | title (המלצה) |
|---|---|
| `/` | שירה עזרא \| צילום ווידאו |
| `/video` | וידאו \| שירה עזרא |
| `/business` | תדמית ועסקים \| שירה עזרא |
| `/events` | אירועים \| שירה עזרא |

תיאור ייחודי לכל עמוד לפי הטקסט שסופק. Sitemap + robots.txt.

**חסר:** תמונת OG, אישור נוסחי מטא, דומיין ל־canonical.
